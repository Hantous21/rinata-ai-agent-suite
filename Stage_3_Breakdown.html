Why Data Cleaning Matters

Raw data collected from the real world is almost never ready for analysis. It needs to be inspected, standardized, and enriched before you can trust the results. Garbage in, garbage out — AI categorization on dirty data produces unreliable outputs.

The cleaning step is where you build trust in your dataset. After Stage 3, you can say with confidence:

  • Every row has a valid rating (1–5)
  • Every row has a valid date and day of week
  • No duplicate reviews are counted twice
  • Text is normalized (no hidden extra spaces or line breaks)
  • Rating-only reviews are clearly flagged and won't confuse the AI
Industry context: Data professionals estimate that 60–80% of real-world data work is cleaning and preparation — not analysis. This stage is not glamorous, but it's what separates reliable insights from misleading ones.

What Is pandas?

pandas is the most widely used Python library for data analysis. It introduces a data structure called a DataFrame — think of it as a spreadsheet inside Python. Each column has a name and a data type, each row is a record, and you can filter, transform, group, and aggregate the data with clean, readable code.

Without pandas, you'd use nested Python lists and dictionaries, writing manual loops for every operation. With pandas, operations that would take 20 lines become 1 line.

Step-by-Step Code Breakdown

Step 1

Fixing Data Types

df["rating"] = pd.to_numeric(df["rating"], errors="coerce").astype("Int64")

df["has_owner_response"] = df["has_owner_response"].map(
    {"True": True, "False": False}
)

When pandas reads a CSV, it doesn't know what type each column should be — everything starts as text (strings). We need to tell it what each column actually represents:

  • pd.to_numeric(errors="coerce") — converts the rating column from strings like "5" to actual numbers. The errors="coerce" means: if a value can't be converted (e.g. it says "five"), turn it into NaN (Not a Number) instead of crashing.
  • .astype("Int64") — converts to integer. We use the capital Int64 (not int64) because it can handle NaN values — regular Python integers can't be null.
  • .map() — replaces values using a lookup dictionary. The CSV stored True/False as text strings — .map() converts them to real Python booleans.
Key concept — Data types matter:
If rating stays as a string, then rating > 3 would compare strings alphabetically ("5" > "3" works, but "10" < "3" because "1" comes before "3"). Converting to a numeric type ensures comparisons work as expected mathematically.
Step 2

Normalizing Review Text

df["review_text"] = (
    df["review_text"]
    .fillna("")
    .str.strip()
    .str.replace(r"\s+", " ", regex=True)
)

This is a method chain — multiple operations applied in sequence, each transforming the result of the previous one. Reading left to right:

  • .fillna("") — replaces any NaN (missing) values with an empty string. Prevents crashes when you try to call string methods on NaN.
  • .str.strip() — removes leading and trailing whitespace from every review. Some scraped text has invisible spaces at the start or end.
  • .str.replace(r"\s+", " ", regex=True) — collapses multiple spaces or newlines into a single space. The \s+ is a regex meaning "one or more whitespace characters (space, tab, newline)."
Why normalize whitespace?
The AI in Stage 4 reads the review text. Extra whitespace wastes tokens (and therefore money), and inconsistent formatting can subtly confuse models. A clean, consistent input produces more consistent AI output.
Step 3

Flagging Rating-Only Reviews

df["has_text"] = df["review_text"].str.len() > 0

This single line creates a new boolean column by asking: "is the length of the review text greater than zero?" The result is True for reviews with text, False for rating-only reviews.

209 out of 597 reviews (35%) had no written text — just a star rating. We keep these rows because the rating itself is still useful for aggregate analysis (average score by day, etc.), but we flag them so the AI categorization step in Stage 4 can skip them cleanly.

Design decision — keep vs. delete:
A common instinct is to delete rows that don't have text. We chose to keep them and flag them instead. This preserves the integrity of the full dataset for rating-based analysis, while still making it easy to filter to text-only reviews when needed: df[df["has_text"] == True].
Step 4

Checking for True Duplicates

text_reviews = df[df["has_text"]].copy()
dupes = text_reviews.duplicated(
    subset=["review_text", "rating"],
    keep="first"
)
true_dupes = dupes.sum()

We only check for duplicates among reviews with text — otherwise every empty review would match every other empty review (since they all have the same text: ""). That's why Stage 2's naive duplicate count showed 209 "duplicates" — they were all the rating-only rows.

  • .duplicated(subset=[...]) — marks a row as duplicate if the combination of those columns appeared in an earlier row. keep="first" means the first occurrence is kept; subsequent matches are flagged.
  • .sum() — counts True values in the boolean series. In Python, True == 1 and False == 0, so summing a boolean column gives the count of True values.
  • Result: 0 true duplicates — all 388 text reviews are unique.
Step 5

Adding Derived Columns

df["text_length"]  = df["review_text"].str.len()
df["word_count"]    = df["review_text"].str.split().str.len().fillna(0).astype(int)
df["is_positive"]   = df["rating"] >= 4
df["is_negative"]   = df["rating"] <= 2
df["is_neutral"]    = df["rating"] == 3
df["date_approx"]   = pd.to_datetime(df["date_approx"], errors="coerce")
df["year_month"]    = df["date_approx"].dt.to_period("M").astype(str)

Derived columns are computed from existing data. They don't add new raw information, but they make downstream analysis much easier — instead of writing df[df["rating"] >= 4] every time you want positive reviews, you just write df[df["is_positive"]].

Notable patterns:

  • .str.split().str.len() — a double .str accessor chain. First .split() turns each string into a list of words. Then .str.len() counts the items in each list. Result: word count per review.
  • pd.to_datetime() — converts the date string column ("2026-04-20") into actual Python datetime objects that pandas understands as dates. Without this, you can't use date math or the .dt accessor.
  • .dt.to_period("M") — converts each date to a calendar month period (2026-04). The "M" stands for "month." This lets you group and count reviews by calendar month.

The Duplicate Mystery — A Debugging Lesson

Debugging

Why did the first scan show 209 duplicates?

Before writing the cleaning script, a quick inspection of the raw CSV showed 209 duplicate review texts. That sounded alarming — had the scraper collected the same reviews twice?

The answer was no. The 209 "duplicates" were all the rating-only reviews. Each one had review_text = "" (empty string). Since all empty strings are identical, pandas counted each one as a duplicate of the first empty review.

The fix was to run the duplicate check only on rows where has_text == True — excluding empty reviews from the comparison entirely. The result: 0 true duplicates.

Lesson: Always understand why a number looks suspicious before acting on it. "209 duplicates" initially looked like a scraper bug. One extra query revealed it was a side effect of empty values — not a data collection problem. Investigating before deleting saved 209 valid data points.
Debugging

Windows terminal Unicode error — the "★" and "→" crash

The cleaning script crashed twice on print() statements that contained the "→" arrow and "★" star characters. The error was:

UnicodeEncodeError: 'charmap' codec can't encode character '→'

The Windows Command Prompt and PowerShell default to a character encoding called CP1252 (Windows Western European), which only supports 256 characters — far fewer than Unicode's 143,000+. Characters like "→" and "★" simply don't exist in CP1252.

Fix: Replace Unicode symbols in print statements with ASCII equivalents — -> instead of →, "5 star" instead of "★★★★★".

Key concept — Character encoding:
Computers store text as numbers. A character encoding is the rulebook that says which number maps to which character. ASCII (128 characters) is universal. UTF-8 (covers all of Unicode) is the modern standard. CP1252 is a legacy Windows encoding. Mismatches between what a script tries to print and what the terminal supports cause UnicodeEncodeErrors. Python files and CSV files can be UTF-8, but the terminal display is a separate encoding controlled by the OS.
